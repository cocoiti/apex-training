# 画面の操作のキーとパッドのボタンはアクションの経路に入れず、押し始めだけを画面ごとの操作に変える

状態: 承認

## 背景

やり直す・次へ・やめる・もう一度・武器変更を、キーボード（R・Space・Q）とパッド（A / ×・B / ○）でも操作できるようにする
（screens.md「画面の操作」）。これらは入力方式の設定によらず受け付け、照準と射撃のアクションにも入力の記録にも入れない。
パッドは押し続けても繰り返さず、画面が変わる前から押していたボタンは一度離すまで次の画面の操作にしない（UI-37）。

## 決定

- 画面の操作は `ScreenControl`（`r` / `space` / `q` / `pad-a` / `pad-b`）として、`Action` とは別の経路で受ける
  （`src/input/screen-controls.ts`）。`emit` にも `RecordingInput` にも渡さない。
- キーは `keydown` の `code` で見て、`repeat` と修飾キー付き（Ctrl+R など）は捨てる。入力欄に入力しているときも捨てる。
- パッドは `PadButtons` が描画ごとに読み、前回読んだときに離していたボタンが押されたときだけ操作にする。
  つないだ直後に押していたボタンも一度離すまで操作にしない。一時停止中も読み、押し始めを捨てる。
- 何の操作になるかは画面とプレイ画面の状態（練習中・短いリザルト・一時停止中）から `screenCommand` で決める
  （`src/ui/screen-commands.ts`）。操作にならなかった Space は既定の動作（スクロールなど）を止めない。

## 却下した案

- A / × などを新しい `Action` にしてキューに積む: 入力の記録に入り、再生（INP-4）と記録の形に影響する。
  入力方式の切替で経路が差し替わるので、マウスに固定したときにパッドで操作できなくなる（UI-38）。
- パッドのボタンを押している間の状態で操作にする（画面が変わったら押下を無視する印を付ける）: 画面の変わり目ごとに
  印を付け直す処理が要る。押し始めだけを見れば、押し続けたボタンは次の画面で自然に操作にならない。
