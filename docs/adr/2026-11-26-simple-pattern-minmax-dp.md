# 簡易版のパターンは練習の始めに sim の純粋関数が動的計画法で厳密に求め、武器の JSON にも設定にも持たせない

状態: 承認

## 背景

weapons.md「簡易版のパターン」は、理想の補正軌道を 5 本以下の折れ線で近似し、頂点を発の点から選ぶ。選び方は
「本数を 1 本から増やし、その本数で最大の差が最も小さい折れ線が許容差 1.0 度以下になった最初の本数を使う。同じ最大の差なら
本数の少ないもの、頂点の発の番号を前から比べて小さいもの」と決まっている（WPN-24〜WPN-28）。
`measured` の武器を JSON で足すとコードを変えずに簡易版も出る必要がある（WPN-29）。補正のパネルだけが使い、
弾痕・採点・ゴースト・パッドのガイド・リザルトは詳細版のまま変えない（UI-66, UI-68）。

## 決定

- `simplePattern`（src/sim/simple-pattern.ts）が `magSize` と `pattern` だけから求める。DOM と Three.js に触れない純粋関数。
- 求め方は動的計画法。区切り a→b の差の最大を全組で前もって求め（O(n³)、n は装弾数）、`rest[k][a]`（a 発目から最後までを
  ちょうど k 本で結ぶときの最大の差の最小）を後ろから求める。頂点は前から、目標の値を超えない最も小さい次の頂点を選ぶので、
  同じ最大の差の中で頂点の番号が前から小さい折れ線になる。値は同じ計算の max なので、等しさを誤差なしで比べられる。
- 練習の始め（`CorrectionPanel.begin`）に 1 回だけ求める。55 発の武器でも 1〜2 ms。
- 表示の範囲は詳細版の理想の補正軌道から決め、簡易でも同じにする（UI-67）。パネルの次の発の点だけを簡易版での位置にする。
- 区切りの言葉の一覧はパネルの中の `ol` に置き、強調（`li.current`）が変わったときだけ innerHTML を書き直す。

## 却下した案

- 武器の JSON に簡易版の頂点を手で書く・ビルドで書き出す: SPEC が自動で求めると決めており、データの形が増え、pattern と食い違いうる。
- Douglas–Peucker などの近似: 本数の上限と「最大の差が最も小さい」の両方を満たす保証がなく、WPN-24 の判定と選び方が SPEC と一致しない。
- 頂点の組をすべて試す: 55 発・5 本で約 300 万通り（C(54,4)）になり、練習の始めに毎回行うには重い。
- 簡易版を sim の発射やゴーストにも渡す: 覚えるための表示だけに使う決定（weapons.md）に反し、採点と記録の再生が設定で変わる。
