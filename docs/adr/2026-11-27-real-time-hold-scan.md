# 倒している・押している長さを実時間で決めていないかは、押す書き方から離す書き方までの間に時計を進めているかで調べる

状態: 承認

## 背景

ARC-68 は、ブラウザのテストのコードに、スティックを倒している長さやボタンを押している長さを実時間（決まった ms のタイマー、
performance.now() の時刻まで待つ処理）や描画の回数で決めている箇所がないことを求める。ARC-22（固定の sleep）と同じく、
テストのコードを調べて確かめたい。書き方はファイルごとの小さな関数（`__btn`・`__setR2`・`mouseButton` など）で、
ページで評価する文字列の中にも書かれる。

## 決定

- `tests/helpers/test-code.ts` の `findRealTimeHolds` が、コードの文字列も含めて行ごとに、練習の入力（右スティックの軸 2・3、
  R2・L2、マウスのボタン）を倒す・押す書き方から戻す・離す書き方までを「押している間」とし、その間に時計を進める書き方
  （advanceClock・advanceClockUntil）がなく、描画・条件・実時間を待っているものを示す。`tests/architecture/test-code.test.ts` が
  すべてのブラウザのテストのファイルで空であることを確かめる。
- 時計を進めていれば clock=manual のページなので、間に実時間で待っても示さない（ARC-67 を確かめるテストの書き方）。
- ファイルの中で定義した関数は本体の書き方で見なす。clock=manual かどうかで待ち方を変える関数（時計がなければ実際の描画を待つ）は、
  時計を進める関数と見なさない。
- A・B などの画面の操作のボタンとキーボードのキーは見ない（押し始めだけが操作になり、長さで結果が変わらない）。

## 却下した案

- 実行時に調べる（ページで入力の押下と時計の進みを記録し、押している間に時計が進まなかったら失敗にする）: すべてのテストの
  パッドの偽物に手を入れることになり、Chromium がない環境では確かめられない。
- TypeScript の構文木で呼び出しの流れを追う: 押す・離すの多くがページで評価する文字列の中にあり、構文木では見えない。
- 名前に印（コメントの指示）を付けた箇所だけを除く: 書き手が付け忘れても見つけられず、除くことが簡単になりすぎる。

## 影響

- spec/architecture.md（テストのための描画の省略と時計の差し替え、ARC-68）
- tests/helpers/test-code.ts, tests/architecture/test-code.test.ts, tests/acceptance/README.md と、ブラウザを使う受け入れテスト
