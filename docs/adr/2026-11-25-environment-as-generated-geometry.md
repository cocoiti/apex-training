# 壁のパネル・的のリング・床・空は画像のテクスチャでなく、コードで作る形（三角形と線）で描き、レイに当てない

状態: 承認

## 背景

#33 で壁を「的のリングと 1 メートルのパネルの壁」にし、床と空を足す（screens.md「3D の表示」、UI-18〜UI-20、UI-23）。
リングは目の位置から見た角度で決めた半径 D × tan(θ) の円で、的の箱の正面と壁の正面の両方に描き、箱の縁で途切れずにつながって見える必要がある。
単体テストは node で動き（ADR: render-scene-without-webgl）、DOM の canvas も WebGL もない。見た目は描画だけのもので、当たり判定・採点に影響してはならない。
受け入れテストはヘッドレスの Chromium（ソフトウェアの描画）で動き、描画が重いと時刻に敏感なテストが落ちる。

## 決定

- `src/render/environment.ts` で、リング・中心点・パネル・目地・床の格子を三角形と線の形として作る。リングは、開始時の照準の向きと
  各箱の目の側の面が交わる点を中心に、その面の距離 D から半径を求め、面の長方形で切り取る（Sutherland–Hodgman）。
- 表示物はすべて `raycast` を空にし、レイはマップの箱（壁・的）だけに当たる。シミュレーションは見た目を参照しない。
- パネルは目の側を向いた面にだけ描く（プレイヤーは開始の位置から動かない）。パネルの明るさの違いは位置からのハッシュで決め、毎回同じにする。
- 光の計算をしない材質（MeshBasicMaterial）で決めた色のまま描き、ライトは置かない。空の球は最後に奥行きを比べて描き、隠れた画素を塗らない。
  リングは面ごとに縁取りと暗い線の 2 つの形にまとめ、床の格子は目の近くだけ、目から 1, 2, 4, … m で区切った線分にする
  （カメラの後ろへ抜ける長い線分は、ソフトウェアの描画で丸ごと欠けた）。

## 却下した案

- CanvasTexture（2D の canvas に描いた画像）: node のテストで作れず、リングの半径を数で確かめられない。距離によって線がぼやける。
- DataTexture などで画素を作って貼る: 面ごとの D が違うので面ごとに解像度を決める必要があり、箱の縁でのつながりを確かめにくい。
- シェーダーで円を描く: 形を node で確かめられず、WebGL の環境ごとの差を受け入れテストでしか見られない。
- 光を当てる材質（MeshLambertMaterial）のまま: 色が光の向きで変わって色を決めにくく、ソフトウェアの描画で 1 フレームが倍以上重くなった。
