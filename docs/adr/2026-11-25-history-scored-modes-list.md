# 履歴の画面のモードの選択肢は、採点するモードの id と名前の固定の一覧から作る

状態: 承認

## 背景

SPEC（docs/spec/screens.md「履歴の画面」、UI-18）は、履歴の画面のモードの選択肢を採点するモード（ゴースト追従・センター維持）だけにし、
パターン観察を出さないことを求める。モードの一覧（src/modes/registry.ts）は登録されたファイルから作るが、
採点するかどうかは練習を終えたときの `result().scored` で初めて分かり、モードの型には静的な印がない。
また、ゴースト追従のモードのファイルはまだなく、登録された一覧からはセンター維持しか取れない。

## 決定

- `src/ui/history-view.ts` の `SCORED_MODES` に、採点するモードの id と表示名を並び順（ゴースト追従 `ghost`、センター維持 `center`）で持つ。
- 履歴の画面のモードの選択肢と、開いたときの既定の組（最初の採点するモード）はこの一覧から作る。
- 登録されたモードと id が同じものは名前が一致することを単体テスト（tests/ui/history-view.test.ts）で確かめる。

## 却下した案

- 登録されたモードの一覧から作る: 採点するかが静的に分からず、ゴースト追従のファイルがない今は UI-18 を満たせない。
- モードの型（`TrainingMode`）に `scored` の印を足して登録から絞る: 全モードと登録の検査を変える型の変更になり、
  ゴースト追従のファイルがない問題も残る。採点しないモードが増えるなど、固定の一覧で足りなくなったときに改めて決める。

## 影響

- docs/spec/screens.md（履歴の画面、UI-16, UI-18）
- src/ui/history-view.ts、src/main.ts
- 採点するモードを足すときは `SCORED_MODES` にも足す。
