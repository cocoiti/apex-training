# パッド向けのガイドと入力推移の理想は、ステップの入力を適用する前の状態から求め、ガイドの表示はゴーストの表示に従わせる

状態: 承認

## 背景

pad.md「パッド向けのガイド」は、理想の補正速度を「fire の状態と次に撃つ弾」から求め、練習中はガイドに、リザルトでは
入力推移のグラフの理想の推移に使う。固定ステップの中では「入力の適用 → 射撃」の順に状態が変わるので、どの時点の状態で
求めるかで理想の推移が 1 ステップずれる。PAD-20 は、ガイドに合わせて倒した記録から作ったグラフで自分と理想が一致することを求める。
ガイドを出す条件（ゴースト追従・ゴースト表示 ON・撃ち切り前・練習中）も、ゴーストの条件とほぼ重なる。

## 決定

- 理想の補正速度は `src/sim/weapon.ts` の `idealCorrectionRate`（武器と fire・次に撃つ弾・残弾から求める純粋な関数）1 か所で求める。
- 練習中のガイドは、描画のたびに今の状態（直前のステップの終わり）で求める（`PracticeSession.idealRate`）。
  パッドの look は次のステップの開始で、そのとき読んだスティックの値から作るので、ガイドに合わせて倒した値は次のステップで使われる。
- リザルトの理想の推移（`src/sim/trajectory.ts` の `lookRateTrace`）は、記録を再生し、ステップ n の理想を
  ステップ n の入力を適用する前の状態で求める。ガイドがステップ n のスティックの値を読むときに表示していたものと同じになる。
  ADS の状態は、自分・理想のどちらもステップ n の入力を適用したあとの記録の ads で決める。
- 再生は Gun だけを動かし、箱のない World と固定の種で進める（次に撃つ弾は fire の時刻と残弾だけで決まり、当たりとブレに依らない）。
- ガイドは「設定のゴースト表示が ON・`session.ghost` が undefined でない・今の入力方式がパッド」のときだけ出す。
  ゴーストを持たないモード（センター維持・パターン観察）、撃ち切り、練習の終わりはゴーストの条件がそのまま当てはまる。
- ガイドはプレイ画面の HTML と CSS の重ね表示で描く（`src/ui/pad-guide.ts`、index.html の .pad-guide）。

## 却下した案

- 理想をステップ n の入力と射撃を適用したあとの状態で求める: ガイドで見た位置に倒しても 1 ステップずれ、PAD-20 で一致しない。
- TrainingMode にガイド用の関数を足す: 条件がゴーストと同じで、モードごとに同じ判定を重ねるだけになる。
- 推移の再生に PracticeSession と元の World を使う: 終わった練習の World は書き換わっており、モードの状態も作り直す必要がある。
- ガイドを Three.js の層に描く: 画面上の固定の位置に出す 2D の表示で、スコープと同じく HTML の重ね表示のほうが軽く試しやすい。
