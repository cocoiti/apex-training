# localStorage は例外を投げない SafeStorage を通し、失敗後もページを開いている間はメモリで値を持つ

状態: 承認

## 背景

プライベートウィンドウや保存の拒否では、`window.localStorage` の参照・`setItem`・`getItem` が例外になる。
SPEC（docs/spec/overview.md「保存」、OVR-4）は、その環境でもエラーで止まらずに練習でき、
起動時の試しの書き込みか起動後の保存で失敗したら、ページを開いている間は保存できないことを表示し続けることを求める。
設定と自己ベストを保存する画面はこれから複数の Issue で足される。

## 決定

- localStorage への読み書きはすべて `src/ui/storage.ts` の `SafeStorage`（アプリでは `appStorage`）を通す。
  `window.localStorage` は関数で受け取り、使うときに初めて参照する（参照そのものの例外も捕まえる）。
- 例外は呼び出し側に投げない。`set` は保存できたかを真偽値で返し、`get` は読めなければ `null` を返す。
- 書いた値はメモリにも持ち、`get` はこのページで書いた値を優先して返す。保存できない環境でも、変えた設定はページを開いている間は効く。
- 一度でも書き込みに失敗したら「保存できない」状態にし、ページを開いている間は戻さない。
  `onUnavailable` の登録者に 1 回だけ知らせ、フッターの表示（`showStorageNotice`）はこれを受けて出す。

## 却下した案

- 呼び出し側（設定・自己ベストの各画面）がそれぞれ try/catch する: 書き忘れると OVR-4 が壊れ、表示の出し方もばらつく。
- 失敗した値を捨てる（メモリに持たない）: 保存できない環境では、設定を変えても同じページの中で読み返せず、変えた設定が効かない。
- 書き込みに成功したら「保存できない」の表示を消す: SPEC が「ページを開いている間は消えない」と決めており、
  一部だけ保存された状態を「保存できる」と見せてしまう。

## 影響

- docs/spec/overview.md（OVR-4）、src/ui/storage.ts、src/ui/shell.ts、src/main.ts
- 設定（docs/spec/screens.md UI-2）と自己ベストの保存は `appStorage` を使う。
