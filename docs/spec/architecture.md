# 構成と拡張性

## 概要

将来のキャラコン（移動テクニック）練習を作り直しなしで足せるよう、MVP の段階から固定タイムステップの
シミュレーション、アクションベースの入力、モードのプラグイン化、入力の記録と再生を持つ。
キャラコン自体は MVP の範囲外（[docs/roadmap.md](../roadmap.md)）。

## 用語

| 用語 | 意味 |
|------|------|
| シミュレーション | 照準・射撃・リコイル（将来は移動）の計算。`src/sim/` |
| 固定ステップ | シミュレーションを進める一定の時間間隔。既定 1/120 秒で、定数で変えられる |

## 振る舞い

### 固定ステップと描画の分離

- シミュレーションは固定ステップで進め、描画は画面の更新に合わせて別に行う。描画はシミュレーションの結果を補間して表示する。
- 同じ入力なら、表示のフレームレートが違ってもシミュレーションの結果は同じになる。

### シミュレーションの独立

- `src/sim/` は Three.js と DOM に依存しない。ブラウザなしでテストから実行できる。
- 照準と弾道は 3D のベクトル（ヨー・ピッチの角度 → 方向ベクトル → 的とのレイの交差）で計算する。
- リコイルによる照準のズレは、カメラの向きに加える独立したオフセットとして持つ。

### 決まった結果

- シミュレーションの結果は入力の記録と乱数の種だけで決まる（[input.md](input.md) の入力の記録と再生）。

### モードとマップの追加

- 練習モードは共通の型（`id`、`name`、`category`（recoil / movement / combined）、準備、ステップごとの処理、結果、片付け）で作る。
- 練習の場所（マップ）は箱の組み合わせを `src/data/maps/` の JSON で定義する。
- プレイヤーは状態（MVP では「立ち止まって撃つ」だけ）を持ち、状態を足せる形にする。

### フォルダ構成

```
src/
  core/      固定ステップのループ、時間、種付きの乱数、イベント
  input/     アクション定義、キーボード・マウス、パッド、割り当て、記録と再生
  sim/       World、Player（状態）、武器・リコイル、当たり判定
  modes/     練習モード（recoil/, movement/, combined/）
  render/    Three.js のシーン・カメラ・弾痕・ガイド
  ui/        メニュー・設定・リザルト（HTML/CSS）
  data/      weapons/, maps/
```

## 受け入れ条件

- **ARC-1**: `src/sim/` 以下のファイルが `three` と DOM の API を import・参照していないことを、テストで確認できる
- **ARC-2**: 同じ入力の記録をシミュレーションに 60Hz 相当と 144Hz 相当の描画間隔で与えたとき、弾痕の位置と採点結果が一致する
- **ARC-3**: `src/sim/` のシミュレーションを、ブラウザなしのテスト（Vitest）から入力の記録だけで実行できる
