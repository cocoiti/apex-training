# 全体と制約

## 概要

ブラウザだけで Apex Legends の武器のリコイル（反動）制御を練習できる、非公式のファンツール。
マウスかパッドで撃ち、理想の補正軌道（ゴースト）と自分の補正のズレを可視化・採点する。
あわせて、左右に動く的を照準で追い続ける追いエイム（リコイルあり・なし）と、ランダムに出る的へ素早く照準を合わせて撃つフリックも練習できる（[modes.md](modes.md)「追いエイム」「フリック」）。
入力は「エイムアシストなしの素のリコイル制御」の練習に限り、ゲームの外で使える補正の出力は持たない。

## 用語

| 用語 | 意味 |
|------|------|
| リコイル | 1 発ごとに照準が跳ね上がる量（度）。武器ごとのパターンで決まる |
| 補正 | 利用者がリコイルを打ち消すために照準を動かすこと |
| ゴースト | 理想の補正軌道（リコイルのパターンを上下左右に反転したもの）を示す点 |
| ADS | 覗き込み（エイム）中の状態 |
| 入力方式 | マウス、またはパッド（コントローラー） |

## 振る舞い

### 対応環境

- PC のブラウザ（Chrome を主対象）でマウスとパッドを使える。
- タッチ操作だけの端末には対応しない。パッドを接続したタブレットなどでは、パッドで遊べる。

### 権利と表記

- EA / Respawn の画像・ロゴ・武器モデル・効果音を使わない。武器名はテキストだけで表示する。
- すべての画面のフッターに、非公式ファンツールであり EA / Respawn とは無関係である旨を表示する。日本語のときは「非公式ファンツールであり、EA / Respawn とは無関係」、
  英語のときは `Unofficial fan tool. Not affiliated with EA or Respawn.` と表示する（表示の言語は下の「表示の言語」）。
- 効果音は自作したものか、Web Audio で合成したものだけを使う。
- 画像・音声・3D モデルは自作したものを基本とし、外部の素材は許可した OSS 系のライセンスのものだけを使う（「素材の一覧」の「許可するライセンス」）。
- 画像・音声・3D モデルを配布物に含めるときは、出どころとライセンスを素材の一覧に記録する（「素材の一覧」）。

### 素材の一覧

- 配布物（ビルド結果）に含めてよい画像・音声・3D モデルは、出どころを素材の一覧（`src/assets/assets.json`）に記録したものだけとする。
  対象の拡張子は次のとおり（大文字・小文字は区別しない）。
  - 画像: png・jpg・jpeg・gif・webp・avif・bmp・ico・svg
  - 音声: mp3・wav・ogg・m4a・aac・flac・opus・weba
  - 3D モデル: glb・gltf・fbx・obj・dae・3ds・blend・usdz
- 素材の一覧は JSON で、素材のファイルごとに 1 項目を持つ配列とする。各項目には次の 4 つを空でない文字列で書く。

  | 項目 | 内容 |
  |------|------|
  | `path` | 素材のソースファイルのリポジトリのルートからのパス（例: `src/assets/icons/play.svg`、`public/favicon.svg`） |
  | `author` | 作者（自作の素材は「自作」かこのリポジトリの作者の名前、外部の素材は素材の作者の名前） |
  | `license` | 「許可するライセンス」の表の値のどれか（例: `self-made`、`CC0-1.0`、`MIT`） |
  | `source` | 出どころの説明。自作の素材はどう作ったか、外部の素材は配布元の URL（`http://` か `https://` で始まる）を含めて書く |

#### 許可するライセンス

- `license` に書けるのは次の表の値だけとする。値は表のとおりに書き、大文字・小文字も区別する（前後の空白は除いて比べる）。
  `MIT OR Apache-2.0` のような複数のライセンスを組み合わせた書き方は認めない（使うライセンスを 1 つ選んで書く）。

  | 値 | 種類 | 内容 |
  |----|------|------|
  | `self-made` | 自作 | このリポジトリの作者が作った素材。このリポジトリのライセンスに従う |
  | `CC0-1.0` | OSS 系（SPDX 識別子） | Creative Commons Zero v1.0 Universal |
  | `CC-BY-4.0` | OSS 系（SPDX 識別子） | Creative Commons Attribution 4.0 International |
  | `CC-BY-SA-4.0` | OSS 系（SPDX 識別子） | Creative Commons Attribution Share Alike 4.0 International |
  | `MIT` | OSS 系（SPDX 識別子） | MIT License |
  | `Apache-2.0` | OSS 系（SPDX 識別子） | Apache License 2.0 |
  | `BSD-2-Clause` | OSS 系（SPDX 識別子） | BSD 2-Clause "Simplified" License |
  | `BSD-3-Clause` | OSS 系（SPDX 識別子） | BSD 3-Clause "New" or "Revised" License |
  | `OFL-1.1` | OSS 系（SPDX 識別子） | SIL Open Font License 1.1 |

- 自作（`self-made`）に含めるのは、作者が自分で描いた・録った・モデリングした素材と、作者がツールを操作して作った素材
  （画像の編集ソフト、Web Audio などの音の合成、プログラムによる生成）。外部の素材を加工したものは元の素材のライセンスを書く。
  画像・音声・3D モデルを作る生成 AI が出力した素材は自作に含めず、表にもないため使わない。
- 名前（作者・出どころの文字列）で公式の素材かどうかは判定しない。EA / Respawn の素材を使わないことは「権利と表記」の決まりとして守り、
  検査は許可したライセンスかどうかだけを見る。

- ビルド結果のファイルは、次のどちらかに当たるとき一覧に載っているとみなす。
  - `public/` の下の素材: ビルド結果のルートからのパスが、一覧の `path` から先頭の `public/` を除いたものと一致する。
  - それ以外の素材: ファイル名からビルドが付けるハッシュ（`<名前>-<ハッシュ>.<拡張子>` の `-<ハッシュ>`）を除いた名前と拡張子が、一覧の `path` のファイル名と一致する。
- 画像・音声・3D モデルは、ビルドで JS や CSS に data: URL として埋め込まず、ファイルとして出す。
- 検査のコマンド（`npm run check:assets`）は、ビルド結果（既定は `dist/`。引数でフォルダを渡せる）と素材の一覧を調べ、
  次のどれかに当たるときは、当たったファイルのパスか一覧の項目（`path`）と理由をすべて示して 0 以外の終了コードで終わる。
  どれにも当たらないときは成功する。素材が 1 つもなく一覧が空の配列のときも成功する。
  - ビルド結果に、一覧に載っていない画像・音声・3D モデルのファイルがある。
  - 一覧の項目に `path`・`author`・`license`・`source` のどれかがない、または空の文字列である。
  - 一覧の項目の `license` が「許可するライセンス」の表にない値である（理由として「許可していないライセンス」とその値を示す）。
  - 一覧の項目の `license` が OSS 系の値なのに、`source` に配布元の URL（`http://` か `https://` で始まる部分）がない。
  - 一覧の項目の `path` のファイルがリポジトリにない、または対象の拡張子でない。
  - 素材の一覧のファイルがない、または JSON として読めない、または配列でない。
- 一覧で防げるのは記録のない素材と許可していないライセンスの記載の混入までで、一覧の記載が正しいか（自作と偽っていないか、書いたライセンスが本当か）は検査では確かめない。

### 練習の範囲

- ブラウザ内での練習に限る。ゲームの起動中にマウスを自動で動かす機能や、補正値をアプリの外へ出力する機能
  （ファイル、外部デバイス、ほかのアプリとの連携）は持たない。
- 練習の結果を外へ渡すのは、リザルト画面とセットのまとめの「結果をシェア」と「X に投稿」（[screens.md](screens.md)「結果のシェア」）だけとする。
  渡すのは成績の要約の短い文（アプリの名前と非公式ファンツールである旨、武器とモードの名前、平均ズレと命中率、
  またはセットの回数とセットの平均ズレ、自己ベストを更新したか、公開 URL）だけで、補正値・照準の軌道・パターンの数値・入力の記録・画像は含めない。
  文は外部のサーバーへ送らず、ブラウザのシェアの機能・クリップボード・X の投稿画面のリンクに渡すだけとする。
- 計測（下の「画面の表示の計測」）を許可した人について、画面の表示（画面の名前とパス）だけを Google Tag Manager に渡す。
  成績・照準の動き・補正値・パターンの数値・入力の記録・設定の値は渡さない。
- パッドのエイムアシストは再現しない。パッドの設定画面に「エイムアシストなしの素のリコイル制御を練習する」と表示する。

### 表示の言語

- 画面の文言は日本語と英語のどちらかで表示する。最初の言語はブラウザの言語で決め（`ja` で始まるときは日本語、それ以外は英語）、設定画面で切り替えられ、選んだ言語は保存する
  （[screens.md](screens.md)「表示の言語」）。
- アプリの名前は、どちらの言語でも「Hyper Aim Training」と表記する。武器名などの固有の表記も言語によらず同じにする。
- 対応する言語は日本語と英語の 2 つだけとする。

### 公開

- サーバー処理のない静的サイトとして、リポジトリ名のサブパス（`/apex-training/`）で公開できる。
- 画面はハッシュ（`#/settings` など）で切り替える。どの画面の URL を直接開いても、その画面が表示される。
  どの画面にも当たらないハッシュ（ハッシュなしを含む）を開いたときは、トップ画面を表示する。
- 3D のキャンバスを画面いっぱいに置き、その上に各画面の HTML を重ねる。
- 公開先は GitHub Pages の `https://cocoiti.github.io/apex-training/` で、リポジトリの `gh-pages` ブランチのルートを配信する。
- 公開は手動で行う。公開のコマンド（`npm run deploy`）は次のことを行う。
  - 作業ツリーに未コミットの変更（追跡しているファイルの変更、ステージした変更、追跡していないファイル。無視されたファイルは除く）があるときは、
    その旨を示して 0 以外の終了コードで終わり、ビルドも push もしない。公開したものは、コミットメッセージに書く今の HEAD のコミットと一致する。
  - ビルドし、ビルド結果（`dist/` の中身）と空の `.nojekyll` を `gh-pages` ブランチのルートに置いてコミットし、origin へ push する。
    `gh-pages` ブランチのルートには、今回のビルド結果と `.nojekyll` だけが残る（前回の公開の古いファイルは消える）。
  - 作業は一時的な作業ツリー（`git worktree`）で行い、終わったら片付ける。実行したときの作業ツリー（未コミットの変更を含む）、
    今のブランチ、既定ブランチは変わらない。
  - ビルドか push が失敗したときは、その旨を示して 0 以外の終了コードで終わり、`gh-pages` ブランチを中途半端な状態で push しない。

### 保存

- 設定と自己ベストと練習の履歴はブラウザの localStorage に保存する。localStorage が使えない環境（プライベートウィンドウ、
  保存の拒否など）でも、保存されないだけで練習はできる。
- 起動時に localStorage へ試しに書き込み、例外になったとき、または起動後の保存で書き込みが例外になったときは、
  すべての画面のフッターの非公式の表記のすぐ上に「この環境では設定と記録を保存できません。練習はそのまま続けられます。」と表示する。
  この表示はページを開いている間は消えない。
  英語のときは `Settings and records can't be saved in this environment. You can keep practicing.` と表示する。

### 画面の表示の計測

画面の表示回数を、計測を許可した人についてだけ、Google Tag Manager（GTM）を通して計測する。GTM のコンテナの中の設定
（Google Analytics 4 のタグなど）はアプリの外で行う。

- コンテナ ID は、ビルドの設定の 1 か所に置く。公開するビルドのコンテナ ID は `GTM-MNFCCG6N`。
  コンテナ ID が空のときは、計測に関わることを何もしない（同意の案内を出さず、設定画面に計測の区分を出さず、GTM を読み込まず、
  `dataLayer` を作らない）。以下はコンテナ ID があるときの振る舞い。
- 同意の状態は「未選択」「許可」「許可しない」のどれかで、localStorage のキー `apex-training:analytics-consent` に
  `granted`（許可）か `denied`（許可しない）を保存する。値がない、またはほかの値のときは未選択として扱う。
- 同意の案内（[screens.md](screens.md)「計測の同意の案内」）で「許可」か「許可しない」を選ぶか、設定画面の計測の区分
  （[screens.md](screens.md)「計測の設定」）で切り替えると、同意の状態が変わって保存される。
- 許可でないあいだ（未選択・許可しない）は、GTM のスクリプトを読み込まず、`googletagmanager.com` へ要求を出さない。
  `dataLayer` も作らず、アプリも GTM も Cookie を作らない。GTM の `noscript` の `iframe` も置かない（HTML に最初から書かない）。
- 許可になったとき（許可が保存された状態でページを開いたとき、または案内か設定画面で許可を選んだとき）は、ページを開いているあいだに 1 回だけ
  `dataLayer` に `{ "gtm.start": <今の時刻のミリ秒>, "event": "gtm.js" }` を積み、
  `https://www.googletagmanager.com/gtm.js?id=<コンテナ ID>` を非同期のスクリプトとして読み込む。
  続けて、そのとき表示している画面の画面の表示を 1 回積む。
- 画面の表示: 許可のあいだ、表示する画面がハッシュの切替で変わるたびに、`dataLayer` に次の 3 つの項目だけを持つ 1 件を積む。

  | 項目 | 値 |
  |------|----|
  | `event` | `page_view` |
  | `screen_name` | 表示した画面の名前（下の表） |
  | `page_path` | ベースパスとその画面のハッシュ（例: `/apex-training/#/settings`）。URL のクエリは含めない |

  | 画面 | `screen_name` | `page_path` のハッシュ |
  |------|---------------|----------------------|
  | トップ | `top` | `#/` |
  | 設定 | `settings` | `#/settings` |
  | プレイ | `play` | `#/play` |
  | リザルト | `result` | `#/result` |
  | 履歴 | `history` | `#/history` |
  | セットのまとめ | `set-result` | `#/set-result` |
  | パッドのキャリブレーション | `pad-calibration` | `#/settings/pad` |
  | パッドのボタン割り当て | `pad-mapping` | `#/settings/pad/mapping` |

  - 値は実際に表示した画面で決める。どの画面にも当たらないハッシュや、直接開いてトップ画面に戻した `#/play` などは、トップ画面の表示として 1 件だけ積む。
  - 画面が変わらないあいだ（やり直し・連続練習の各回・短いリザルトはプレイ画面のまま）は積まない。同じ画面を開き直しただけのハッシュの変化でも、表示する画面が変わらなければ積まない。
- アプリが `dataLayer` に積むのは、上の GTM の開始の 1 件と画面の表示だけとする。練習の開始・終了などの出来事、成績、照準の動き、補正値、
  パターンの数値、入力の記録、設定の値、武器・モードの選択は積まない。
- 許可を取り消したとき（設定画面で計測を OFF にしたとき）は、「許可しない」を保存し、このサイトの Cookie のうち名前が `_ga` で始まるものと `_gid` を消して、
  ページを読み込み直す。読み込み直したあとは GTM を読み込まず、画面の表示を積まない。
- localStorage が使えない環境（上の「保存」で保存できないと表示する環境）では、同意の案内を出さず、未選択として扱う（GTM を読み込まない）。
  設定画面の計測の区分では切り替えられ、許可を選ぶとそのページを開いているあいだだけ計測する。
- GTM のコンテナにはどんなタグでも足せるため、アプリが GTM に渡すのは画面の表示だけであり、それ以外の情報を集めない設定（画面の表示のほかに
  ページの内容やクリックなどを集めるタグを足さないこと）にするのは GTM を運用する側の責任とする。

## 受け入れ条件

- **OVR-1**: どの画面を開いたときも、フッターに非公式ファンツールであり EA / Respawn と無関係である旨が表示される
- **OVR-2**: ビルド結果に、素材の一覧に載り `license` が許可した値の画像だけがある（または画像・音声・3D モデルが 1 つもない）状態で検査のコマンドを実行したとき、成功する
- **OVR-3**: サブパス `/apex-training/` に配置したビルド結果で `#/settings` を直接開いたとき、設定画面が表示され、武器データの読み込みが 404 にならない
- **OVR-4**: localStorage への書き込みが例外になる環境でアプリを開いて練習を始めたとき、エラーで止まらずに画面が表示されて練習でき、フッターの非公式の表記のすぐ上に「この環境では設定と記録を保存できません。練習はそのまま続けられます。」と表示される
- **OVR-5**: アプリのどの画面にも、補正値や照準の動きをファイルや外部デバイスへ出力する操作がない。外へ渡す操作は「結果をシェア」と「X に投稿」だけで、渡すのは成績の要約の文だけである
- **OVR-6**: どの画面にも当たらないハッシュ（`#/unknown` など）やハッシュなしで開いたとき、トップ画面が表示される
- **OVR-7**: 公開のコマンドを実行したとき、`gh-pages` ブランチのルートにビルド結果と `.nojekyll` が置かれ（ビルド結果にないファイルは残らず）、実行前後で既定ブランチ、今のブランチ、作業ツリーの内容は変わらない
- **OVR-8**: 公開した `https://cocoiti.github.io/apex-training/#/settings` を直接開いたとき、設定画面が表示され、武器データの読み込みが 404 にならない
- **OVR-9**: 作業ツリーに未コミットの変更か追跡していないファイルがある状態で公開のコマンドを実行したとき、その旨を示して 0 以外で終わり、`gh-pages` ブランチと作業ツリーは変わらない
- **OVR-10**: 素材の一覧に載っていない画像（`dist/assets/unknown.png` など）をビルド結果に置いて検査のコマンドを実行したとき、そのファイルのパスと「一覧に載っていない」旨を示して 0 以外で終わる
- **OVR-12**: 素材の一覧に `license` などの必須の項目がない、または空の文字列の素材があるとき、検査のコマンドはその素材の `path` と欠けている項目の名前を示して 0 以外で終わる
- **OVR-13**: 素材の一覧の `path` がリポジトリにないファイルを指しているとき、検査のコマンドはその `path` とファイルがない旨を示して 0 以外で終わる
- **OVR-14**: 素材の一覧に載った画像を `src/` から読み込んでビルドしたとき、その画像は data: URL に埋め込まれずにビルド結果のファイルとして出て、検査のコマンドは成功する
- **OVR-15**: ビルド結果の素材がすべて一覧に載り、一覧の項目の `license` がすべて `self-made` であるとき、検査のコマンドは成功する
- **OVR-16**: ビルド結果の素材がすべて一覧に載り、一覧に `license` が `CC0-1.0` で `source` に配布元の URL（`https://` で始まる）を含む項目があるとき、検査のコマンドは成功する
